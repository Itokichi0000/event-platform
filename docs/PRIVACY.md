# サーバーが見るもの・保存するもの

この文書はプロジェクトの信用の根拠です。テーブル・列・ログ出力を追加・変更するコミットでは、
必ずこの文書も同じコミットで更新してください（CLAUDE.md のルール）。

最終更新：フェーズ2（運営機能）

各項目は `apps/server/test/privacy.test.ts` と `apps/server/test/phase2.test.ts` でテストとして確認しています。

## 参加者を表すテーブルは存在しない

サーバーの DB にあるのは次の10テーブルだけです（スキーマの正本は `apps/server/src/db/migrations.ts`）。
参加者（人）を表すテーブルはなく、発行と支払い・消し込み・IP アドレス・入場時刻を結びつける列もありません。

| テーブル        | 列                                                                                                                                                                                                                                                                         | 何のためか                                              | 保持期間                                       |
| --------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------- | ---------------------------------------------- |
| hosts           | pubkey                                                                                                                                                                                                                                                                     | 主催者の識別（NIP-98 で初めて操作したとき登録）         | 退会まで                                       |
| events          | id, host_pubkey, title, description, starts_at, ends_at, location, location_visibility, capacity, issue_policy, price_msat, issued_count, redeemed_count, returned_count, offline_checkin, nwc_enc, status, cover_image, cover_mime, cover_version, created_at, updated_at | イベント情報と集計値                                    | 主催者が削除するまで（nwc_enc は終了48時間後） |
| event_cohosts   | event_id, pubkey                                                                                                                                                                                                                                                           | 共同主催者                                              | イベントと同じ                                 |
| keysets         | id, event_id または host_pubkey, kind, public_key, private_key_enc                                                                                                                                                                                                         | ブラインド署名の鍵。秘密鍵は暗号化して保存              | ticket・room の秘密鍵は終了48時間後に削除      |
| spent           | keyset_id, y                                                                                                                                                                                                                                                               | 使用済み・返却済みチケットの照合値 `Y = hashToCurve(x)` | 終了48時間後に削除                             |
| quotes          | id, event_id, payment_hash, state, expires_at                                                                                                                                                                                                                              | 有料チケットの請求書                                    | 終了48時間後に削除（未払いは期限の1時間後）    |
| invite_codes    | id, event_id, code_hash, label, max_uses, uses_left                                                                                                                                                                                                                        | 招待コード。コードは鍵付きハッシュのみ                  | イベント終了まで                               |
| checkin_buckets | event_id, bucket_start, count                                                                                                                                                                                                                                              | 15分ごとの来場数（ダッシュボードのグラフ）              | イベントと同じ                                 |
| announcements   | id, event_id, body, created_at                                                                                                                                                                                                                                             | お知らせ                                                | イベントと同じ                                 |
| scanner_links   | id, event_id, token_hash, label, expires_at, revoked_at, created_at                                                                                                                                                                                                        | 受付リンク。トークンはハッシュのみ                      | 期限（終了6時間後）まで                        |

補足：

- **spent** には時刻の列も「返却か入場か」の区別もありません。`WITHOUT ROWID` で作っているため、
  保存順からも消し込みの順番は分かりません。
- **checkin_buckets** は件数だけを持ち、どのチケット（`y`）がどの時間帯に入場したかは記録しません。
  ただし来場者が少ない時間帯では「その15分に1人来た」ことは分かります。
- **quotes** には支払った人の情報（ノード、名前、コメントなど）を入れません。請求書の文字列そのものも保存しません。
  どの quote でどのブラインド値に署名したかも記録しません。
- **nwc_enc** は主催者のウォレット接続文字列（NWC）を暗号化したものです。請求書の作成と確認にだけ使い、
  主催者向けの API でも返しません。
- **invite_codes.code_hash** は HMAC（マスター鍵から導いた鍵）なので、DB が漏れても短いコードを総当たりできません。
- **cover_image** は主催者がアップロードした画像そのもの（512KB まで）。外部 URL の画像は参加者の IP を
  第三者に送ってしまうため受け付けません。
- 鍵セットの秘密鍵と NWC 接続文字列は、マスター鍵（環境変数 `KAMEN_MASTER_KEY`）から HKDF で導いた鍵で
  AES-256-GCM 暗号化し、行の識別子を関連データにしています。
- SQLite は `secure_delete = ON` で開き、削除した値が空き領域に残らないようにしています。

## 削除ジョブ

サーバーは15分ごとに `apps/server/src/jobs/cleanup.ts` を実行します。

| いつ                   | 消すもの                                                                  |
| ---------------------- | ------------------------------------------------------------------------- |
| イベント終了時         | 招待コード                                                                |
| 受付リンクの期限       | 受付リンク                                                                |
| 請求書の期限の1時間後  | 未払いの quote                                                            |
| イベント終了の48時間後 | ticket・room の秘密鍵、その使用済みリスト、すべての quote、NWC 接続文字列 |

48時間後に残るのは、イベント情報、公開鍵、集計値（発行・来場・返却の数、15分ごとの来場数）、お知らせだけです。

## リクエストごとにサーバーに届く値

| 場面                                     | 届く値                                                      | 保存するもの                                                                                |
| ---------------------------------------- | ----------------------------------------------------------- | ------------------------------------------------------------------------------------------- |
| イベント閲覧 `GET /events/:id`           | イベント ID                                                 | なし                                                                                        |
| PoW 課題 `POST /events/:id/quote`        | イベント ID                                                 | なし（課題は HMAC 付きでステートレス）                                                      |
| 請求書 `POST /events/:id/quote`（有料）  | イベント ID                                                 | quote（payment_hash、状態、期限）                                                           |
| 支払い確認 `GET /events/:id/quotes/:qid` | quote ID                                                    | 状態の更新のみ                                                                              |
| 発行 `POST /events/:id/issue`            | PoW の解・招待コード・quote ID のいずれか、`keysetId`、`B_` | `issued_count + 1`、招待コードの残り回数 − 1、quote を `issued` に。`B_` と署名は保存しない |
| 返却 `POST /events/:id/return`           | `keysetId`、`secret`(=`x`)、`C`                             | `spent` に `y`、`issued_count − 1`、`returned_count + 1`                                    |
| 消し込み `POST /events/:id/redeem`       | 受付トークン、`keysetId`、`secret`(=`x`)、`C`               | `spent` に `y`、`redeemed_count + 1`、時間帯の件数 + 1                                      |
| 使用済みリスト `GET /events/:id/spent`   | 受付トークン                                                | なし（オフライン受付のイベントのみ。`y` の一覧を返す）                                      |
| 主催者 API                               | NIP-98 署名またはセッション（pubkey）、入力内容             | 入力内容と pubkey                                                                           |

発行時に見た `B_` と、消し込み・返却時に見た `x` を結びつける計算はできません（ブラインド署名）。

**メモリ上だけに置くもの**：使用済みの PoW 課題 ID と NIP-98 トークンの署名を、期限（PoW は既定10分、
NIP-98 は2分）まで重複利用の防止に使います。有料イベントでは、請求書が出ている間だけ主催者のウォレットとの
NWC 接続と入金通知の購読を保ちます。いずれもディスクには書きません。サーバーを再起動すると忘れるため、
再起動直後は期限内の PoW 解を一度だけ再利用される可能性があります。

### 有料チケット

請求書は主催者のウォレットが NWC（NIP-47）で作り、支払いは主催者に直接届きます。サーバーは資金を預かりません。

- サーバーが知るのは「この quote の請求書が支払われた」ことだけです。支払った人のノードや経路は分かりません
  （ウォレット側の主催者には、Lightning の性質上、通常の受け取りと同じ情報が見えます）。
- 支払い済みの quote 1つにつき1回だけ発行できます。quote は発行時に `issued` になりますが、どの `B_` に署名したかは残しません。
  支払いの時刻と発行の時刻は近いので、サーバーは「この quote で発行された」ことは分かります。
  それでも、発行されたチケットがどれか（どの `x` か）は分かりません。
- 返却しても返金はされません（サーバーが資金を持たないため）。

### 招待コード

コードを1人ずつ配った場合、主催者は「どのコードが使われたか」から「その人がチケットを取ったこと」を知ります。
誰が実際に来たかは分かりません。総当たりを防ぐため、招待制のイベントでもコードに加えて PoW を求めます。
招待リンクではコードを URL のフラグメント（`#invite=…`）に置き、サーバーやプロキシのログに残らないようにしています。

### 共同主催者

共同主催者は npub で追加します。サーバーが保存するのはその公開鍵だけです。共同主催者ができるのは、イベントの編集、
お知らせ、受付リンクの発行、集計の閲覧です。中止、ウォレット、招待コード、共同主催者の管理は主催者本人だけができます。

### 主催者のセッション

主催者は NIP-07 拡張で NIP-98 イベントに1回署名し、8時間有効のセッショントークンと交換します
（`POST /api/host/session`）。トークンは `pubkey|有効期限` に HMAC を付けたもので、サーバーには保存しません。
ブラウザでは Cookie ではなく sessionStorage に置くため、タブを閉じると消えます。

### 受付リンク

受付リンクは `/scan/<イベントID>#<トークン>` の形で、トークンを URL のフラグメント（`#` 以降）に置きます。
フラグメントはブラウザがサーバーへ送らないため、プロキシのログや Referer に残りません。
サーバーはトークンの SHA-256 だけを保存します。

### 「チケット保持者にだけ表示」の場所

場所を隠したイベントでは、場所を発行のレスポンスに含めて渡します。場所を見るためにあとからチケットを
提示する必要がないので、閲覧と入場が結びつきません。

### DLEQ（とブラインド係数 `r`）とオフライン受付

チケットに付く NUT-12 の DLEQ 証明 `{e, s, r}` の `r` があれば `B_ = Y + rG` を計算し直せます。
もしサーバーが方針に反して発行時の `B_` を記録していたら、発行と入場を結びつけられてしまいます。

- **受付の QR**：オフライン受付を有効にしたイベントだけ DLEQ を載せます（`encodeQrToken()`）。
  参加者の端末は、チケット画面を開くたびにイベントの設定を取り直し、QR に反映します。
- **消し込み・返却 API**：DLEQ を含むリクエストは拒否します。サーバーは秘密鍵で `C = kY` を直接検証します。
- **参加者の端末とバックアップ文字列**：DLEQ を常に残します（参加者自身の手元から出ないため）。

オフライン受付を有効にしたイベントでは、受付端末（主催者側）が `r` を見ます。改造した受付端末と、
`B_` を記録するよう改造したサーバーを組み合わせれば結びつけは可能です。主催者の設定画面、参加者のイベントページ、
チケット画面にこの点を表示します。

オフライン受付では、複数の受付端末が同時にオフラインだと二重入場を防ぎきれません。端末は復帰時に同期し、
他の端末で使用済みだったチケット（競合）を一覧で表示します。

## ルーム（Marmot）

ルームは任意です。チケットの取得と入場には関係しません。

### 誰が何を読めるか

| 相手                               | 読めるもの                                                                                                                                                                                                                                                                                                       |
| ---------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| リレー運営者                       | 暗号文だけ。グループメッセージ（kind 445）はイベントごとに新しい使い捨て鍵で署名され、タグはグループのルーティング ID（`h`）だけ。参加者宛ての Welcome（kind 1059）には受信者の使い捨て公開鍵（`p`）が付く。**ルームに入った参加者のブラウザはリレーに直接接続するので、リレーには参加者の IP アドレスが見える** |
| ルームエージェント（このサーバー） | **ルームの会話を読める。** エージェントはグループ唯一の管理者メンバーで、MLS の鍵を持つ。会話は保存もログ出力もしないが、サーバーを改造すれば読める。チケットと違い、ルームではサーバーを信頼する必要がある                                                                                                      |
| 他の参加者                         | 会話と、各参加者の使い捨て公開鍵（そこから決まる仮面と名前）。普段の npub は使わない                                                                                                                                                                                                                             |

### リレーに出さないもの

- 参加者の鍵パッケージ（kind 30443）は、リレーに公開せず、入室パスと一緒に `POST /room/join` でエージェントへ渡す。
- 参加者はリレーリスト（kind 10002 / 10050）を公開しない。
- Welcome はリレーに出すのに加えて、`room/join` の応答でも返す。

### 入室パス

チケットと同時に、別の鍵セット（room）でブラインド署名した入室パスを1枚発行する。サーバーは入室時にパスを消し込むが、
鍵セットが別なので、入室パスとチケット（入場）は結びつかない。発行時の `B_` は保存しない。

### ルームエージェントが保存するもの

エージェントは API サーバーとは別のプロセスで、別の SQLite（`AGENT_DB_PATH`）を使う。

| テーブル | 列                                                                                                         | 保持期間 |
| -------- | ---------------------------------------------------------------------------------------------------------- | -------- |
| rooms    | event_id, room_id（MLS グループ ID）, ends_at                                                              | 解散まで |
| kv       | event_id, namespace, key, value_enc（MLS のグループ状態など。マスター鍵から導いた鍵で AES-256-GCM 暗号化） | 解散まで |

- 会話の本文、参加者の一覧、参加者と入室パスの対応は保存しない（MLS の状態にはメンバーの使い捨て公開鍵が含まれる）。
- エージェントの Nostr 鍵はイベントごとにマスター鍵から導くので、イベントをまたいでエージェントの公開鍵からルームを結びつけられない。
- イベント終了の24時間後（または主催者の操作）でグループを解散し、上の行をすべて削除する。参加者のブラウザも解散を検知すると、端末内の履歴と使い捨て鍵を消す。
- API サーバーとエージェントは内部 HTTP でつなぎ、マスター鍵から導いた共有シークレットで認証する。エージェントのログはメソッド・ルートパターン・ステータス・所要時間だけ。

## ログ

- サーバーのリクエストログは `メソッド ルートパターン ステータス 所要時間` の1行だけです
  （例：`POST /api/events/:id/redeem 200 4ms`）。具体的な ID、クエリ、ヘッダー、本文は出しません。
- 内部エラーはエラー名とメッセージだけを出し、リクエストの内容は出しません。
- 削除ジョブは削除した件数だけを出します。
- 同梱の Caddy 設定はアクセスログを無効にし、`X-Forwarded-For`・`X-Real-IP`・`User-Agent` を
  サーバーへ転送しません（`deploy/Caddyfile`）。

## 保存しないもの

- IP アドレス、User-Agent（ログにも DB にも残さない）
- メール、氏名、電話番号、参加者の npub、支払った人の情報
- チケット発行時のブラインド値 `B_`、ブラインド署名 `C_`、請求書の文字列
- 発行と支払い、発行と消し込みの対応
- Cookie（API はクッキーを発行しない）、アクセス解析、外部 CDN・外部フォント

## ブラウザに保存するもの

| 誰の           | 場所           | 中身                                                                                     |
| -------------- | -------------- | ---------------------------------------------------------------------------------------- |
| 参加者         | IndexedDB      | チケット（`secret`、`C`、DLEQ）、イベント情報のコピー（タイトル、日時、場所、受付方式）  |
| 参加者         | IndexedDB      | 支払い待ちの quote（quote ID と請求書）。発行後に削除                                    |
| 受付スタッフ   | IndexedDB      | オフライン受付用：イベントの公開鍵、使用済みの照合値 `y`、未同期の消し込み。同期後に整理 |
| 主催者         | sessionStorage | セッショントークンと pubkey（タブを閉じると消える）                                      |
| すべての利用者 | localStorage   | 表示言語（`ja` / `en`）のみ                                                              |
| すべての利用者 | Service Worker | アプリ本体（HTML・JS・CSS）のキャッシュ。API の応答はキャッシュしない                    |

参加者のチケットはサーバーに送りません（返却するときは、そのチケットを使えなくするために `x` と `C` を送ります）。
バックアップ文字列は参加者が自分でコピーしたときだけ端末の外に出ます。
外部 CDN・外部フォント・解析スクリプトは読み込みません（Caddy の CSP でも `'self'` 以外を拒否）。

## 守れないもの

- 会場で顔は見られる。
- 参加者が少ないイベントでは匿名集合も小さい（5人なら5人）。
- Tor や VPN を使わなければ、通信経路上の第三者やサーバーのホスティング事業者には IP アドレスが見える。
- サーバーが訪問者ごとに別の公開鍵を配れば、チケットに印を付けられる。DLEQ 検証は「公開されている鍵で
  署名された」ことしか保証しない。対策（公開鍵の第三者公開・比較など）は今後の課題。
- チケットは持参人式。QR を見た人はそのチケットを使える。
- 有料チケットでは、Lightning の支払い経路の性質上、主催者のウォレットに通常の受け取りと同じ情報が見える。
