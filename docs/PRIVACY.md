# サーバーが見るもの・保存するもの

この文書はプロジェクトの信用の根拠です。テーブル・列・ログ出力を追加・変更するコミットでは、
必ずこの文書も同じコミットで更新してください（CLAUDE.md のルール）。

最終更新：フェーズ1（無料イベントのMVP）

各項目は `apps/server/test/privacy.test.ts` でテストとして確認しています。

## 参加者を表すテーブルは存在しない

サーバーの DB にあるのは次の7テーブルだけです（スキーマの正本は `apps/server/src/db/migrations.ts`）。
参加者（人）を表すテーブルはなく、発行と支払い・消し込み・IP アドレス・入場時刻を結びつける列もありません。

| テーブル        | 列                                                                                                                                                                                                                               | 何のためか                                      | 保持期間                                               |
| --------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------- | ------------------------------------------------------ |
| hosts           | pubkey                                                                                                                                                                                                                           | 主催者の識別（NIP-98 で初めて操作したとき登録） | 退会まで                                               |
| events          | id, host_pubkey, title, description, starts_at, ends_at, location, location_visibility, capacity, issue_policy, price_msat, issued_count, redeemed_count, status, cover_image, cover_mime, cover_version, created_at, updated_at | イベント情報と集計値                            | 主催者が削除するまで                                   |
| keysets         | id, event_id または host_pubkey, kind, public_key, private_key_enc                                                                                                                                                               | ブラインド署名の鍵。秘密鍵は暗号化して保存      | ticket・room の秘密鍵は終了48時間後に削除（フェーズ2） |
| spent           | keyset_id, y                                                                                                                                                                                                                     | 使用済みチケットの照合値 `Y = hashToCurve(x)`   | 鍵セットと同じ                                         |
| checkin_buckets | event_id, bucket_start, count                                                                                                                                                                                                    | 15分ごとの来場数（ダッシュボードのグラフ）      | イベントと同じ                                         |
| announcements   | id, event_id, body, created_at                                                                                                                                                                                                   | お知らせ                                        | イベントと同じ                                         |
| scanner_links   | id, event_id, token_hash, label, expires_at, revoked_at, created_at                                                                                                                                                              | 受付リンク。トークンはハッシュのみ              | イベントと同じ                                         |

補足：

- **spent** には時刻の列がなく、`WITHOUT ROWID` で作っているため保存順からも消し込みの順番は分かりません。
- **checkin_buckets** は件数だけを持ち、どのチケット（`y`）がどの時間帯に入場したかは記録しません。
  ただし来場者が少ない時間帯では「その15分に1人来た」ことは分かります。
- **cover_image** は主催者がアップロードした画像そのもの（512KB まで）。外部 URL の画像は参加者の IP を
  第三者に送ってしまうため受け付けません。
- 鍵セットの秘密鍵はマスター鍵（環境変数 `KAMEN_MASTER_KEY`）から HKDF で導いた鍵で AES-256-GCM 暗号化し、
  鍵セット ID を関連データにしています。
- SQLite は `secure_delete = ON` で開き、削除した値が空き領域に残らないようにしています。

## リクエストごとにサーバーに届く値

| 場面                               | 届く値                                        | 保存するもの                                           |
| ---------------------------------- | --------------------------------------------- | ------------------------------------------------------ |
| イベント閲覧 `GET /events/:id`     | イベント ID                                   | なし                                                   |
| PoW 課題 `POST /events/:id/quote`  | イベント ID                                   | なし（課題は HMAC 付きでステートレス）                 |
| 発行 `POST /events/:id/issue`      | PoW の解、`keysetId`、`B_`                    | `issued_count + 1` のみ。`B_` と署名は保存しない       |
| 消し込み `POST /events/:id/redeem` | 受付トークン、`keysetId`、`secret`(=`x`)、`C` | `spent` に `y`、`redeemed_count + 1`、時間帯の件数 + 1 |
| 主催者 API                         | NIP-98 署名（pubkey）、入力内容               | 入力内容と pubkey                                      |

発行時に見た `B_` と消し込み時に見た `x` を結びつける計算はできません（ブラインド署名）。

**メモリ上だけに置くもの**：使用済みの PoW 課題 ID と NIP-98 トークンの署名を、期限（PoW は既定10分、
NIP-98 は2分）まで重複利用の防止に使います。ディスクには書きません。サーバーを再起動すると忘れるため、
再起動直後は期限内の PoW 解を一度だけ再利用される可能性があります。

### 「チケット保持者にだけ表示」の場所

場所を隠したイベントでは、場所を発行のレスポンスに含めて渡します。場所を見るためにあとからチケットを
提示する必要がないので、閲覧と入場が結びつきません。

### DLEQ（とブラインド係数 `r`）の扱い

チケットに付く NUT-12 の DLEQ 証明 `{e, s, r}` の `r` があれば `B_ = Y + rG` を計算し直せます。
もしサーバーが方針に反して発行時の `B_` を記録していたら、発行と入場を結びつけられてしまいます。

- **受付のQR**：オフライン受付を有効にしたイベントだけ DLEQ を載せます（`encodeQrToken()`）。
  フェーズ1にはオフライン受付がないため、QR に DLEQ は入りません。
- **消し込み API**：DLEQ を含むリクエストは拒否します。サーバーは秘密鍵で `C = kY` を直接検証します。
- **参加者の端末とバックアップ文字列**：DLEQ を常に残します（参加者自身の手元から出ないため）。

オフライン受付を有効にしたイベントでは、受付端末（主催者側）が `r` を見ます。改造した受付端末と、
`B_` を記録するよう改造したサーバーを組み合わせれば結びつけは可能です。主催者の設定画面と参加者の
申込画面にこの点を表示します（フェーズ2）。

## ログ

- サーバーのリクエストログは `メソッド ルートパターン ステータス 所要時間` の1行だけです
  （例：`POST /api/events/:id/redeem 200 4ms`）。具体的な ID、クエリ、ヘッダー、本文は出しません。
- 内部エラーはエラー名とメッセージだけを出し、リクエストの内容は出しません。
- 同梱の Caddy 設定はアクセスログを無効にし、`X-Forwarded-For`・`X-Real-IP`・`User-Agent` を
  サーバーへ転送しません（`deploy/Caddyfile`）。

## 保存しないもの

- IP アドレス、User-Agent（ログにも DB にも残さない）
- メール、氏名、電話番号、参加者の npub
- チケット発行時のブラインド値 `B_`、ブラインド署名 `C_`
- 発行と支払い、発行と消し込みの対応
- Cookie（API はクッキーを発行しない）、アクセス解析、外部 CDN・外部フォント

## 参加者のブラウザに保存するもの

IndexedDB に、チケット（`secret`、`C`、DLEQ）とイベント情報のコピー（タイトル、日時、場所）を保存します。
サーバーには送りません。バックアップ文字列は参加者が自分でコピーしたときだけ端末の外に出ます。

## 守れないもの

- 会場で顔は見られる。
- 参加者が少ないイベントでは匿名集合も小さい（5人なら5人）。
- Tor や VPN を使わなければ、通信経路上の第三者やサーバーのホスティング事業者には IP アドレスが見える。
- チケットは持参人式。QR を見た人はそのチケットを使える。
