# サーバーが見るもの・保存するもの

この文書はプロジェクトの信用の根拠です。テーブル・列・ログ出力を追加・変更するコミットでは、
必ずこの文書も同じコミットで更新してください（CLAUDE.md のルール）。

最終更新：フェーズ0（土台）

## 現状

フェーズ0では **サーバーはまだ存在しません**。実装済みなのはブラウザとサーバーで共用する暗号ライブラリ
`packages/core` だけで、このライブラリはネットワーク通信も永続化も行いません。

## 参加者を表すテーブルは存在しない

設計上、サーバーの DB には参加者（人）を表すテーブルを作りません。保存するのはイベント・鍵セット・
「使用済みの照合値」・集計値だけです。

## サーバーに届く値（`packages/core` の API で固定）

| 場面          | サーバーに届く値                | 型                                     | 結びつけられるか                                                       |
| ------------- | ------------------------------- | -------------------------------------- | ---------------------------------------------------------------------- |
| 発行（issue） | `keysetId`, `B_`                | `IssueRequest`                         | `B_ = Y + rG` は乱数 `r` で隠されており、`x` とも `C` とも結びつかない |
| 消し込み      | `keysetId`, `secret`(=`x`), `C` | `RedeemPayload`（`toRedeemPayload()`） | 発行時の `B_` と結びつける計算はできない                               |

### DLEQ（とブラインド係数 `r`）はサーバーへ送らない

チケット（QR）には、受付端末がオフラインでも公開鍵だけで署名を検証できるよう、NUT-12 の DLEQ 証明
`{e, s, r}` が入っています。`r` があれば `B_ = Y + rG` を再計算できるため、もしサーバーが方針に反して
発行時の `B_`（または `e`, `s`）を記録していた場合、発行と入場を結びつけられてしまいます。

そのため受付スキャナーは DLEQ をローカルで検証したあと、`toRedeemPayload()` で DLEQ を取り除き、
`{keysetId, secret, C}` だけをサーバーへ送ります。サーバーは秘密鍵で直接 `C = kY` を検証するので DLEQ は不要です。

**限界**：受付スキャナーの画面（主催者側のスタッフ端末）は QR の中身、つまり `r` を見ます。
悪意ある主催者が改造したスキャナーと、`B_` を記録するよう改造したサーバーを組み合わせれば結びつけは可能です。
公開されたコードのサーバーは `B_` を保存しません（フェーズ1以降、この点を確認できるテストを置きます）。

## 保存予定のもの（フェーズ1以降、docs/SPEC.md 7章）

| テーブル       | 主な列                                                                    | 保持期間                                  |
| -------------- | ------------------------------------------------------------------------- | ----------------------------------------- |
| hosts          | pubkey                                                                    | 退会まで                                  |
| events         | id, host_pubkey, title, …, capacity, issued_count, redeemed_count, status | 主催者が削除するまで                      |
| event_cohosts  | event_id, pubkey                                                          | イベントと同じ                            |
| keysets        | id, event_id / host_pubkey, kind, public_key, private_key（暗号化）       | ticket・room の秘密鍵は終了48時間後に削除 |
| spent          | keyset_id, y（`spentKey(secret)` = `hashToCurve(secret)`）                | 鍵セットと同じ                            |
| quotes         | id, event_id, payment_hash, state, expires_at                             | 終了48時間後に削除                        |
| invite_codes   | event_id, code_hash, uses_left                                            | イベント終了まで                          |
| approvals      | event_id, applicant_pubkey, state                                         | 終了48時間後に削除（承認制のみ）          |
| announcements  | id, event_id, body, created_at                                            | イベントと同じ                            |
| scanner_links  | event_id, token_hash, expires_at                                          | イベント終了まで                          |
| pending_stamps | blinded_hex, signature_hex, expires_at                                    | 24時間                                    |

実装時に実際のスキーマと照合し、この表を更新します。

## 保存しないもの

- IP アドレス、User-Agent（ログにも DB にも残さない。リクエストログはパスとステータスのみ）
- メール、氏名、電話番号、参加者の npub
- チケット発行時のブラインド値 `B_`
- 発行と支払い、発行と消し込みの対応
- Cookie、アクセス解析、外部 CDN・外部フォント

## 守れないもの

- 会場で顔は見られる。
- 参加者が少ないイベントでは匿名集合も小さい（5人なら5人）。
- Tor や VPN を使わなければ、通信経路上の第三者には IP アドレスが見える。
- チケットは持参人式。QR を見た人はそのチケットを使える。
